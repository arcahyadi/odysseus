# PARTIE 10 — CULTURE & COLLABORATION (transversal)

## 10.1 Onboarding

- Documentation d'onboarding permettant à un nouveau dev d'avoir un environnement fonctionnel en moins d'une journée idéalement.
- Un mentor/buddy assigné pour les premières semaines.
- Premières tâches calibrées ("good first issue") pour monter en confiance sans bloquer sur la complexité globale du système.

## 10.2 Documentation & knowledge management

- Documentation as code : versionnée avec le code, revue en PR comme le code lui-même — évite qu'elle diverge silencieusement.
- Base de connaissance centralisée (wiki) pour tout ce qui n'est pas directement lié au code (process, décisions organisationnelles).
- Vigilance sur le **bus factor** (combien de personnes peuvent partir avant qu'une connaissance critique soit perdue) — viser un bus factor > 1 sur chaque brique importante.

## 10.3 Post-mortems sans blâme

- Culture de l'apprentissage plutôt que culture de la faute — un post-mortem qui cherche un coupable pousse à cacher les problèmes plutôt qu'à les signaler tôt.
- Toujours se concentrer sur les causes systémiques (pourquoi le système a permis l'erreur) plutôt que sur l'individu qui l'a commise.

## 10.4 Mentorat & montée en compétence

- Pair programming / mob programming pour transmettre du contexte difficile à documenter.
- Les revues de code comme outil d'apprentissage autant que de contrôle qualité.
- Temps dédié à la veille technologique et à la formation continue — pas uniquement du delivery en continu, sous peine d'épuisement et de stagnation des compétences.
